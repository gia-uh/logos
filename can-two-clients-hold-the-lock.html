Can Two Clients Hold the Lock?

The lock starts free. A acquires it and enters its critical section. B tries to acquire it while A is still inside. There is no enabled acquisition for B, so the model has no B step at that point. A releases the lock, and now B can acquire it.

What would you have to show to rule out both clients being inside after any sequence of steps, including sequences that keep handing the lock back and forth?

Prerequisites. Implication and conjunction from the first proof chapters.

Outcomes. Declare a finite model, choose an inductive invariant, check its three obligations, and replay a run that exposes an incorrect guard.

Every state and every reachable state#

A state records A's location, B's location and the lock owner. Either location can be idle or critical. The owner can be free, A or B. Those independent choices give exactly twelve tuples. In particular, ("critical", "critical", "B") is a state and it violates mutual exclusion. Whether we can get there is a separate question about the steps from the initial state.

from itertools import product
from pathlib import Path

from logos import LogosProofError
from logos.domains.transition_systems import FiniteTransitionSystem

idle, critical, free = "idle", "critical", "free"
locations = (idle, critical)
universe = tuple(product(locations, locations, (free, "A", "B")))
start = (idle, idle, free)
a_inside = (critical, idle, "A")
b_inside = (idle, critical, "B")
both_inside = (critical, critical, "B")

def mutually_exclusive(state):
    a, b, owner = state
    return (a, b) != (critical, critical)

print("Candidate states:", len(universe))
print("Both inside is a candidate:", both_inside in universe)

Candidate states: 12 Both inside is a candidate: True

Take one atomic step at a time. Acquire requires the acting client to be idle and the owner to be free. Release requires that client to be critical and to own the lock. A step updates the acting client's location and the owner, leaving the other client's location alone. Enumerating every source tuple under each guard gives the entire named relation. A false guard contributes no edge.

def declare_lock(*, allow_occupied=False):
    edges = {}
    for index, client in enumerate(("A", "B")):
        acquire, release = [], []
        for source in universe:
            location, owner = source[index], source[2]
            if location == idle and (owner == free or (client == "B" and allow_occupied)):
                target = list(source)
                target[index], target[2] = critical, client
                acquire.append((source, tuple(target)))
            if location == critical and owner == client:
                target = list(source)
                target[index], target[2] = idle, free
                release.append((source, tuple(target)))
        edges[f"{client}.acquire"] = acquire
        edges[f"{client}.release"] = release
    return FiniteTransitionSystem(universe, (start,), edges, mutually_exclusive)

lock = declare_lock()
for name, edges in lock.transitions.items():
    print(name, len(edges), "edges")

A.acquire 2 edges A.release 2 edges B.acquire 2 edges B.release 2 edges

Choose a set that the steps preserve#

Start with three states. When the lock is free, both clients are idle. When one owns the lock, just that client is critical. Try A.acquire from each of these three states. Which ones have an edge under that name? Which candidate state would you miss if you only checked A.acquire?

invariant = (start, a_inside, b_inside)
certificate = Path("two-client-lock.logos")
lock.export_safety(invariant, certificate)
lock.verify_safety(invariant, certificate)
print("Exact lock certificate verified.")

When a step fails#

Remove the free-owner requirement from B's acquire guard. B can now overwrite A's ownership while A stays critical. Try the same trace with both tables.

trace = (("A.acquire", a_inside), ("B.acquire", both_inside))
mutant = declare_lock(allow_occupied=True)
print("Mutant ends in violation:", mutant.replay_violation(start, trace))
try:
    lock.replay_violation(start, trace)
except ValueError as error:
    print("Correct model rejects:", error)

try:
    mutant.export_safety(invariant, Path("invalid-lock.logos"))
except LogosProofError as error:
    print(error)

Mutant ends in violation: ('critical', 'critical', 'B') Correct model rejects: illegal step 2: ('critical', 'idle', 'A') --B.acquire--> ('critical', 'critical', 'B') failed closure under 'B.acquire': ('critical', 'idle', 'A') -> ('critical', 'critical', 'B')

replay_violation checks the start, each named edge and the final predicate. Two acquisitions are enough to violate safety and one cannot do so from the initial tuple. A failed closure obligation alone says the proposed set is inadequate. Here the replay separately shows that the mutated protocol is unsafe. If no certificate or legal violating run has been established, the result is inconclusive.

The standalone lock example exports the same model, verifies a saved certificate against it and replays this trace.

Exit exercise#

Add an atomic A.handoff step from a_inside to b_inside. Keep the four original relations and the initial state. Is the same invariant enough? Fill in handoff_edges in this block and run it. To test the obligation, try adding a second successor both_inside from the same source.

handoff_edges = []  # Add the edge and then try the second successor.
handoff = FiniteTransitionSystem(
    universe, (start,), {**lock.transitions, "A.handoff": handoff_edges},
    mutually_exclusive,
)
path = Path("handoff-exercise.logos")
handoff.export_safety(invariant, path)
handoff.verify_safety(invariant, path)

Instructor solution#

The new edge ends at b_inside, which already belongs to the chosen set. The extra successor would leave the set even though the first successor is safe.

def with_handoff(edges):
    return FiniteTransitionSystem(
        universe, (start,), {**lock.transitions, "A.handoff": edges},
        mutually_exclusive,
    )

handoff = with_handoff([(a_inside, b_inside)])
path = Path("handoff-solution.logos")
handoff.export_safety(invariant, path)
handoff.verify_safety(invariant, path)
print("Handoff solution certificate verified.")

try:
    with_handoff([(a_inside, b_inside), (a_inside, both_inside)]).export_safety(
        invariant, Path("invalid-handoff.logos"),
    )
except LogosProofError as error:
    print(error)

Handoff solution certificate verified. failed closure under 'A.handoff': ('critical', 'idle', 'A') -> ('critical', 'critical', 'B')
